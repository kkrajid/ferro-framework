# Research: PostgreSQL Backend

**Feature**: [spec.md](spec.md) | **Date**: 2026-10-10

## R1. Driver and runtime

- **Decision**: `tokio-postgres` 0.7 inside a new `crates/postgres` (`ferro-postgres`) behind the
  existing `Backend` trait. The backend owns a small Tokio runtime (2 threads, `ferro-pg-*`) and N
  worker tasks, one per pooled connection, pulling jobs from a bounded `async-channel` (1024).
  Completion uses the same callback contract as SQLite, so the Python bridge is unchanged apart from
  choosing backend + dialect by URL scheme.
- **Rationale**: async driver, wire-level control, no ORM layer (constitution III); one connection
  per worker gives transactions an exclusive connection, mirroring the SQLite design.
- **Alternatives**: `sqlx` (own query layer and compile-time macros we do not use); `postgres`
  (sync, wraps tokio-postgres anyway); a pool crate (`deadpool`) — unnecessary for "N workers,
  reconnect on failure".

## R2. Pool behavior

- One connection is opened synchronously at `connect()` to fail fast (bad URL, credentials, host);
  the other workers connect on their first job. A worker whose client reports closed (server
  restart, network) reconnects before its next job (SC-004). A job that was running when the link
  broke fails with `OperationalError`.
- Per-connection prepared-statement cache (256 entries, cleared when full and on reconnect).

## R3. Values (no changes to the ORM's value model beyond one variant)

- **Decision**: add `Value::Decimal(String)` (exact decimal text). The PostgreSQL adapter converts
  `Value`s to the parameter type the server reports for each placeholder:

| Server type | Accepted `Value` | Encoding |
|---|---|---|
| int2/int4/int8 | Integer | range-checked binary |
| bool | Integer (0/1) | binary |
| float4/float8 | Real, Integer | binary |
| numeric | Decimal, Integer, Real | Ferro's binary numeric encoder (base-10000 digits) |
| text/varchar/bpchar/name | Text | UTF-8 |
| date | Text `YYYY-MM-DD` | days since 2000-01-01 |
| timestamptz/timestamp | Text `YYYY-MM-DD HH:MM:SS.ffffff` (UTC) | µs since 2000-01-01 |
| time | Text `HH:MM:SS.ffffff` | µs since midnight |
| uuid | Text | 16 bytes |
| jsonb / json | Text | version byte 1 + UTF-8 / UTF-8 |
| bytea | Blob | raw |

  Results are decoded back into the same textual forms SQLite produces (dates/times as ISO text,
  booleans as 0/1, numerics as `Value::Decimal`), so `from_value` in the bridge needs only the new
  `Decimal` arm. SQLite binds `Value::Decimal` as REAL (unchanged behavior there).
- **Rationale**: keeps the ORM core and Python layer database-independent (FR-014); exact
  decimals (FR-008).

## R4. Dialect differences (`PostgresDialect`)

| Concern | SQLite | PostgreSQL |
|---|---|---|
| placeholder | `?` | `$n` |
| auto key | `INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT` | `bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| types | `decimal(d, p)`, `bool`, `datetime`, `char(36)`, `text` (JSON) | `numeric(d, p)`, `boolean`, `timestamp with time zone`, `uuid`, `jsonb`, `double precision` |
| contains/startswith/endswith | `GLOB` with bracket escaping | `LIKE ... ESCAPE '\'` (case-sensitive) |
| iexact/icontains | `LIKE` (ASCII folding) | `ILIKE ... ESCAPE '\'` (Unicode folding per database ctype) |
| offset only | `LIMIT -1 OFFSET ?` | `OFFSET $n` |
| count/exists over a window | subquery | subquery (alias required before PostgreSQL 16 → always `AS "subquery"`) |

## R5. Bulk inserts without `last_insert_rowid`

- **Decision**: `Job::Batch { statements, returning }`; with `returning = true` every statement is
  run as a query and its first cell collected (`Outcome::Batch { affected, returned }`). Bulk
  inserts become per-row `INSERT ... RETURNING "pk"` in one transaction on both databases
  (single-row `RETURNING` is deterministic on SQLite too).

## R6. TLS (clarified)

- rustls 0.23 with the `ring` provider (builds with the MSVC toolchain; no cmake/NASM), roots from
  `webpki-roots` plus PEM certificates from `sslrootcert`. `tokio-postgres-rustls` 0.14 connects it.
  `disable` → no TLS; `prefer` (default) → TLS when offered, plain otherwise; `require` and
  `verify-full` → TLS mandatory. Certificates are always verified when TLS is used.

## R7. URL handling and secrets

- Ferro parses the query string itself: `pool_size`, `sslrootcert` and `sslmode` are consumed;
  `connect_timeout` and `options` pass through; anything else → `ConfigurationError` listing the
  supported parameters. The remaining URL goes to the driver's parser (handles percent-encoding).
- Error messages are built from host/port/database/user getters, never from the URL string, so the
  password cannot appear (FR-006).

## R8. Errors

| SQLSTATE | Mapping |
|---|---|
| 23505 unique_violation | `Integrity{Unique}`, table from error fields, columns from `Key (a, b)=(...)` detail |
| 23502 not_null_violation | `Integrity{NotNull}`, column from error field |
| 23503 / 23514 | `Integrity{ForeignKey / Check}` |
| 42P01 undefined_table | new `DbError::MissingTable` (SQLite's "no such table" maps here too) → `OperationalError` + create-tables hint |
| other server errors | `Operational` with the server message |
| I/O / closed connection | `Operational("connection to the database was lost: ...")`, worker reconnects |

## R9. Test infrastructure

- Session fixture starts `initdb -A trust -U ferro -E UTF8 --locale-provider=builtin
  --builtin-locale=C.UTF-8` (PostgreSQL 17+; falls back to `--no-locale` on older servers) and
  `pg_ctl start` on 127.0.0.1 with a free port; removed at session end. Binaries are found via
  `FERRO_TEST_PG_BIN`, `PATH`, or `C:/Program Files/PostgreSQL/*/bin`.
- Per test: `psql -c "CREATE SCHEMA t_<random>"` and a URL with `options=-csearch_path=t_<random>`.
- The ORM `database` fixture is parametrized over `sqlite` and `postgres`, so every Feature 002 ORM
  test runs on both (SC-001).
